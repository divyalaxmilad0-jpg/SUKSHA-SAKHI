1. Abstract

Cam phishing is a growing form of online blackmail in which attackers trick women and girls into sharing private images or turning on their webcam, and then use that material to threaten or extort them. Most victims do not know how to identify a suspicious link, detect hidden location data in a photo, or report the crime. Suraksha Sakhi is an interactive web dashboard built with Python and Streamlit to raise awareness of these threats and demonstrate practical protective techniques. The prototype includes a rule-based URL checker, a simulated link-history table, camera-permission alert simulation, a photo EXIF metadata reader and cleaner, safety charts, and a step-by-step victim-support guide. All data displayed in the app is entirely fictional. No machine learning, no real network requests, and no external APIs are used. The project was developed individually as part of the IBM Cybersecurity Bootcamp using IBM Bob as the development assistant.

2. Introduction

The internet has created new forms of crime that specifically target women and girls. One of the most harmful is cam phishing — a trap where an attacker builds a false sense of trust online, persuades a victim to join a video call or share private images, records or captures that material, and then uses it as leverage for blackmail.

Victims of cam phishing are often very young, unfamiliar with cybersecurity, and too afraid or embarrassed to seek help. They may not recognise that a link is dangerous before they click it, or that a photo they are sharing contains their home address embedded invisibly as metadata.

Suraksha Sakhi (meaning "safety companion" in Hindi) is a beginner-friendly Streamlit web dashboard designed to address this gap. It puts protective tools and clear guidance in one place, presented in simple language that any student can understand and use without a cybersecurity background.

3. Problem Statement

Young women and girls who receive suspicious links or video-call requests through WhatsApp, Instagram, SMS, or email have no easy way to:

  • Check whether a link is likely to be a phishing trap before opening it.
  • Understand that photos shared online can carry invisible GPS location data.
  • Know what steps to take if they have already been targeted.
  • Find the correct helpline or reporting portal quickly.

Existing safety awareness content is either too technical for beginners, scattered across different websites, or targeted at adults with prior cybersecurity knowledge. There is no single beginner-friendly tool that combines threat detection, data privacy education, and victim-support guidance in one place.

4. Objectives

  1. To build an interactive web dashboard that demonstrates cam phishing awareness in a format suitable for students and young women.
  2. To implement a rule-based URL checker that analyses a pasted link for five categories of phishing signals without connecting to the internet.
  3. To display and filter fictional link-history and camera-alert records to show how a real monitoring tool might look.
  4. To provide a working EXIF metadata reader that detects GPS location, device model, and date information hidden inside uploaded photos, and produces a clean metadata-free copy for safe sharing.
  5. To present a clear, calm, step-by-step guide for users who have already been targeted, including the official cybercrime helpline number (1930) and the reporting portal (cybercrime.gov.in).
  6. To package everything in a single Python file with beginner-readable comments, so that it can be understood and extended by any student.

5. Scope and Limitations

Scope

  • The prototype runs entirely in a web browser via Streamlit.
  • All features work offline — no internet connection is required after installing the dependencies.
  • The app is designed for educational and awareness purposes, not as a production security tool.
  • Photo metadata processing happens in memory; no files are stored or sent anywhere.

Limitations

  • The link checker uses simple Python rules, not machine learning or real threat intelligence feeds. It may miss sophisticated phishing URLs.
  • The link-history and camera-alert data are entirely fictional and hardcoded — they do not come from a real phone or network.
  • The app is a web prototype and cannot access phone OS permission APIs (Android Accessibility Service or iOS Privacy Report).
  • No user login, database, or persistent storage is used.
  • The app does not scan links automatically in real time; the user must paste a URL manually.

6. Existing Solutions and Their Gaps

Several tools and services address parts of the cam phishing problem:

URL Scanners (e.g., VirusTotal, Google Safe Browsing): These are powerful but require an internet connection, an API key, and some technical knowledge. They are not designed for a beginner who has just received a suspicious link on WhatsApp and needs an instant plain-language answer.
Platform Safety Reports (e.g., Instagram Safety Centre, WhatsApp Help): These provide general guidance but are fragmented across different apps and written for a broad global audience, not specifically for young Indian women targeted by cam phishing.
Cybercrime Reporting Portals (cybercrime.gov.in, helpline 1930): These are essential resources, but they are designed for reporting after the crime has already happened. They do not provide pre-emptive detection or awareness tools.
Photo Metadata Strippers: Some desktop tools can strip EXIF data, but they require the user to already know what EXIF metadata is. Most young users are unaware that their shared photos contain GPS coordinates.
Gap: None of the above solutions combine link detection, photo safety, victim guidance, and safety education in a single beginner-friendly, offline-capable interface designed specifically for the cam phishing threat.

7. Proposed Solution

Suraksha Sakhi is a single-file Python web application built with Streamlit. It provides eight interactive pages accessible from a sidebar navigation menu:

PageWhat it does
🏠 DashboardFour live KPI cards: Links Checked, Safe Links, Suspicious Links, Camera Alerts
🔍 Link CheckerRule-based URL analysis — five checks, a risk score, and a plain-language verdict
📋 Link HistoryFilterable table of 20 fictional link records with colour-coded results
📷 Camera Alerts10 simulated camera/mic/gallery permission events with a risk-level filter
🖼️ Photo SafetyEXIF reader, GPS detector, and Make Safe to Share (metadata stripper)
📊 ChartsTwo bar charts: link results breakdown and risky links by source platform
❓ Help & Tips6-step victim guide (helpline 1930, cybercrime.gov.in) and 6 safety tips
ℹ️ AboutProblem statement, prototype note, and future scope

The entire prototype is contained in one file (app.py) with plain-English comments throughout, so it can serve both as a working tool and as a learning resource for other students.

8. System Architecture

Flow Description

User opens the app in a browser (http://localhost:8501) | v Streamlit renders the sidebar navigation menu | v User selects a page (e.g., "Link Checker") | v The corresponding page block runs inside app.py | +-----+-----+-----+-----+-----+-----+-----+-----+ | | | | | | | | | Dash Link Link Cam Photo Chart Help About board Check Hist Alert Safe Tips | | v v check_link() Pillow EXIF 5 rule checks reader / strip | v All results stored in st.session_state (in-memory, no database) | v Page rerenders — user sees the result instantly

Key Design Decisions

  • Single file: Everything is in app.py. No separate modules, databases, or configuration files. This keeps the project easy to read and run for beginners.
  • No internet calls: The link checker, charts, and tables all run on locally stored data or user input. No external API requests are made.
  • In-memory photo processing: Uploaded photos are opened with Pillow into a Python io.BytesIO object. They are never written to disk or sent to a server.
  • Session state: st.session_state persists counters and the last link-check result across Streamlit's automatic reruns after button clicks.

10. Modules

10.1 Dashboard 🏠

The Dashboard page is the first thing the user sees. It displays four KPI (Key Performance Indicator) cards in a row. Values are derived from the in-memory DataFrames plus any links checked during the session.

CardValue source
🔗 Links CheckedLength of link_history DataFrame + extra checks via Link Checker
✅ Safe LinksCount of "Safe" rows in link_history + extra safe checks
⚠️ Suspicious LinksCount of non-Safe rows in link_history + extra suspicious checks
📷 Camera AlertsCount of "High" risk rows in the cam_alerts DataFrame

A cam-phishing explainer box appears above the cards. All values are derived from fictional in-memory data.

10.2 Link Checker 🔍

The Link Checker lets the user paste any URL and click Check Link. The check_link() function applies five categories of rules and returns a risk score, a verdict, and a plain-language explanation.

Rules, Scores, and Thresholds

RuleConditionScore
1 — URL ShortenerURL contains bit.ly, tinyurl.com, t.co, goo.gl, ow.ly, buff.ly, is.gd, rb.gy, or cutt.ly+30
2 — HTTP (not HTTPS)URL starts with http://+25
3 — IP AddressURL matches regex https?://(\d{1,3}\.){3}\d{1,3}+35
4 — Dangerous KeywordsURL contains any of: free, verify, login, prize, camera, webcam, winner, claim, reward, urgent+20 per keyword
5a — Very Long URLURL length > 75 characters+15
5b — Too Many HyphensURL contains more than 3 hyphens+10 per extra hyphen

Verdict Thresholds

Score RangeVerdictMeaning
0 – 19✅ SafeNo significant risk signals detected
20 – 49⚠️ SuspiciousOne or more mild risk signals; proceed with caution
50 +🚨 DangerousMultiple strong risk signals; do not open this link
Note on session state: Streamlit reruns the entire script on every button click. The result is saved to st.session_state.last_result and rendered in a separate block that runs on every page load, so the verdict is never wiped by the rerun.

10.3 Link History 📋

Shows a filterable table of 20 fictional link records produced by make_history(). Each record has: Time, Source (WhatsApp, Instagram, SMS, Email), Link, Result (Safe / Suspicious / Dangerous). A deliberate cluster of Suspicious and Dangerous links from WhatsApp is included so the Charts page can demonstrate platform-level pattern detection. A Generate Sample Data button refreshes the table. The Result column is colour-coded using a pandas Styler.

10.4 Camera Safety Alerts 📷

Simulates 10 camera, microphone, and gallery permission events produced by make_cam_alerts(). Each record has: Time, App / Site, Permission, Risk (High 5 / Medium 3 / Low 2), Reason. A Risk filter dropdown filters rows while preserving colour coding. A simulation disclaimer clearly states all events are fictional.

10.5 Photo Safety 🖼️

The user uploads a JPG or PNG. Pillow calls _getexif() to extract raw EXIF tags, which are mapped to names using PIL.ExifTags.TAGS. Three specific risks are checked:

  1. 🚨 GPS location (GPSInfo tag) — reveals where the photo was taken.
  2. ⚠️ Device model (Make / Model tags) — reveals the phone or camera used.
  3. ⚠️ Date and time (DateTimeOriginal / DateTime) — reveals when the photo was taken.

The Make Safe to Share button converts the image to RGB, saves it to io.BytesIO without metadata, and presents a download button. The original file is never modified.

10.6 Charts and Filters 📊

Two bar charts built from the link_history DataFrame using st.bar_chart():

  1. Link Results Breakdown — Safe / Suspicious / Dangerous counts in a fixed order using pandas.Series.reindex().
  2. Risky Links by Source — count of non-Safe links per source platform.

A plain-language caption below each chart explains what a healthy or unhealthy pattern looks like.

10.7 Help and Tips ❓

What To Do If You're Targeted — Six collapsible st.expander() steps: (1) Stay calm; (2) Do not pay; (3) Screenshot everything; (4) Block and report; (5) Tell a trusted person; (6) Report to cybercrime.gov.in or call 1930 (emergency: 112). A legal disclaimer box states this is general awareness guidance only.

Safety Tips — Six styled cards in two columns: cover your camera; don't open unknown video-call links; check app permissions; don't share personal photos with strangers; turn off GPS tagging; use strong passwords and 2FA.

14. Ethical Considerations

1. All data is fictional. Every link, IP address, domain name, and app name shown is completely invented. All .example domains are reserved by IANA and will never resolve to a real website.
2. No real surveillance. The app does not monitor real network traffic, read real phone permissions, or interact with any external system. It demonstrates what a real safety tool could look like — it is not a surveillance tool.
3. Suspicious patterns do not prove an attack. The Camera Safety Alerts section includes a clear disclaimer. Users should verify through official channels before taking action.
4. Photos are processed in memory only. Uploaded photos are opened into a Python io.BytesIO object in RAM. They are never written to disk, sent to a server, or logged. The original file is never modified.
5. Supportive tone for victims. The Help & Tips section uses calm, non-judgmental language, states that the crime is the attacker's fault, and provides real official resources (1930, cybercrime.gov.in, 112) rather than invented ones.

16. Conclusion

Cam phishing is a real and growing threat to women and girls online. Most victims lack both the tools and the awareness to protect themselves before harm occurs. Suraksha Sakhi demonstrates that even a small, single-file Python application can provide meaningful educational value: teaching users to identify dangerous links, understand hidden photo metadata, and know exactly where to report a crime.

The prototype was built entirely with free, open-source tools — Python, Streamlit, Pandas, and Pillow — and developed with the assistance of IBM Bob during the IBM Cybersecurity Bootcamp. It is intentionally beginner-friendly, with plain-English comments throughout the code, so that it can serve as a learning resource for other students as well as a working demonstration.

All data in the app is fictional. The project makes no claim to being a production-ready security tool. Its value lies in showing what is possible and in putting the right information in the hands of someone who needs it.
